# Handoff: brain — 3D Particle Cloud Hero

A volumetric 3D particle-cloud rendering of a human brain that serves as the
hero for a personal "second mind" app. The cloud is **fully procedural** — not
a 2D silhouette extruded into depth — generated by a parametric brain function:
an anatomically-proportioned ellipsoid with a longitudinal fissure between
hemispheres, a cerebellum bulge at the back-bottom, and noise-based sulci
across the surface. Five glowing hub neurons sit on anatomical regions of the
cloud and project to HTML labels each frame. Drag to rotate; click a hub to
open a glassmorphic synthesis panel.

---

## About the design files

The files under `source/` are **design references** — an HTML/JSX prototype
running in the browser via Babel-standalone, with Three.js doing the WebGL.
They demonstrate the intended look, motion, and interaction model — they are
**not production code**.

Your job is to **recreate this in the target codebase's existing environment**
(React + a real Three.js / react-three-fiber setup is the natural fit), using
its established patterns, design system, and component libraries. If there is
no existing environment yet, pick the most appropriate framework and implement
there — `@react-three/fiber` + `@react-three/drei` is recommended over the
imperative Three.js code shown here.

When you do recreate this:
- Treat `brain-3d.jsx` as the source of truth for **shape, particle layout, and
  motion timing**. The math (cortex radius, cerebellum, fissure carve, sulci
  noise) is what makes the cloud read as a brain — copy the formulas, don't
  re-derive them.
- Treat `app.jsx` / `neuron-panel.jsx` / `floating-thoughts.jsx` as the source
  of truth for **chrome, copy, and the glass UI** layered on top of the canvas.
- Move ad-hoc inline styles into your design tokens / theme system.
- Drop the in-house `<DesignCanvas>` and `<TweaksPanel>` scaffolding (they're
  review-only chrome and don't ship). Render `<BrainPage mode="3d" />` directly
  into the page, full-bleed.

## The 3D brain (the main thing)

All the core logic is in **`brain-3d.jsx`**. Here's what to know.

### Coordinate system

```
x: lateral             (left  -, right +)
y: anterior-posterior  (front +, back  -)
z: inferior-superior   (top   +, bottom -)
```

A child group inside the rotation root is rotated `-π/2` around X so that the
initial view is **top-down** (camera on +Z looking down) with the front of the
head pointing up on screen.

The camera is a `PerspectiveCamera(fov 32, near 0.1, far 1000)` at
`(0, 0, 4.6)`. The whole brain is then scaled by `BRAIN_SCALE = 1.55` to fill
the frame.

### Procedural shape

The cortex surface is defined by a function `cortexRadius(dx, dy, dz)` that
takes a unit direction and returns the radial distance to the surface in that
direction. It composes:

1. **Anatomical ellipsoid** — `a=1.00, b=1.22, c=0.88` (longest front-back,
   narrowest top-bottom).
2. **Frontal fullness / occipital taper** — `r *= 1 + 0.04·dy` for `dy>0`,
   `r *= 1 + 0.05·dy` for `dy<0`.
3. **Brainstem flatten** — when `dz < -0.45`, shrink `r` proportionally to
   `(-dz - 0.45)`.
4. **Temporal lobe bulge** — adds `0.12 · max(0, |dx|-0.45) · max(0, -dz-0.05)`.
5. **Sulci/gyri noise** — sum of five sines in different frequency bands
   (amplitudes `0.075, 0.060, 0.050, 0.040, 0.030`). This is what makes the
   cloud read as bumpy/folded from any angle rather than smooth-ellipsoidal.
   Don't skip this.

The **cerebellum** is a separate, smaller blob with its own radius function
`cerebellumRadius(dx, dy, dz)` — base axes `(1.0, 0.85, 0.75)`, two finer sine
ridges (folia, amplitudes `0.04` and `0.03`), all scaled by
`CEREB_RADIUS = 0.42`. Its center sits at `CEREB_CENTER = [0, -0.78, -0.42]`
(back, slightly below).

The **longitudinal fissure** between hemispheres is carved by a
`fissureKeep(x, y, z)` function that returns a 0..1 keep-probability:
- Carve only on the dorsal half (`z >= -0.1`).
- Width tapers with `y` so the fissure doesn't cut through the frontal pole.
- Inside the fissure, particles are kept with probability that fades from
  `0.05` at the centerline up to `1.0` outside `fissureWidth + 0.04`.

These three functions together — `cortexRadius`, `cerebellumRadius`,
`fissureKeep` — define the entire shape. **Reproduce them verbatim.**

### Particle layout

Particles are organized as **clusters**, not a uniform fill. Each cluster is a
tight Gaussian-distributed knot of points — these read as "concentrations of
information / memories / thoughts" in the cloud.

| Constant | Value | What it does |
|---|---|---|
| `N_CORTEX_CLUSTERS` | 180 | Discrete cortex neighborhoods |
| `N_CEREB_CLUSTERS`  | 28  | Cerebellum neighborhoods |
| `PARTICLES_PER_CLUSTER_AVG` | 95 | Avg points in each cluster |
| `N_CORTEX_FOG`      | 1800 | Loose volume-filling background scatter |
| `POINT_SIZE`        | 0.020 | Three.js `PointsMaterial.size` |
| `BRAIN_SCALE`       | 1.55 | Final scale-up |
| `ROTATE_SENSITIVITY`| 0.005 | Drag → radians |

Cluster placement:
1. Pick a uniform random direction on the unit sphere (rejection sample inside
   the cube).
2. Compute `R = cortexRadius(dir)`.
3. Place the cluster center at `dir * R * u` where `u ∈ [0.55, 0.97]` —
   clusters live in the outer ~55% of the cortex shell, near the surface.
4. Reject if it would land inside the fissure.
5. Pick a `sigma`: 70% small (`0.045–0.070`), 23% medium (`0.075–0.105`),
   7% large (`0.105–0.135`).
6. Pick `count` from `PARTICLES_PER_CLUSTER_AVG · (0.55 + rand·0.9) ·
   (1.5 if sigma > 0.085 else 1)`.

Cerebellum clusters use the same pattern but with smaller sigma (`0.030–0.055`)
and `count ≈ PARTICLES_PER_CLUSTER_AVG · 0.6 · jitter`.

For each cluster, particles are drawn from an **anisotropic Gaussian**:
`(jx, jy, jz) ~ N(0, σ²)` with `jz` scaled by `0.7` so clusters stretch
slightly tangent to the surface (look like tiny ridges, not perfect balls).
Cortex points are clamped to `len ≤ cortexRadius(unit) · 1.02` so clusters
don't leak outside the shape, and they still respect the fissure carve.

The fog (`N_CORTEX_FOG = 1800`) is a uniform shell scatter at depth
`u = pow(rand, 0.6) · 0.96` from center. It fills the volume between clusters
so the brain shape is still readable in negative space.

### Determinism

The RNG is seeded:
```js
let s = 17;
const rng = () => { s = (s * 9301 + 49297) % 233280; return s / 233280; };
```
This makes the cluster layout **stable across reloads**, which matters — the
brain has a recognizable identity instead of looking different every refresh.
Keep the seed.

### Particle appearance

- A `THREE.Points` cloud with a single 64×64 canvas-generated **soft round
  sprite** as `map` — radial gradient white → pale-blue → transparent. This is
  what gives each point its glow.
- `PointsMaterial { size: 0.020, transparent: true, depthWrite: false,
  blending: AdditiveBlending, vertexColors: true }`.
- Per-vertex color: a subtle vertical (top brighter) and front-to-back gradient.
  Cortex particles use roughly `r ≈ 0.50–0.85`, `g ≈ 0.74–0.98`,
  `b ≈ 0.92–1.00`. Cerebellum points are slightly cooler/dimmer
  (`r ≈ 0.55–0.65, g ≈ 0.78–0.88, b ≈ 0.96`). The exact formulas are in
  `writePoint()` — copy them.
- Additive blending is essential — without it the cloud looks dead. Don't
  swap to normal alpha.

### Hubs

Five hubs sit on the cortex (or cerebellum, for Health). Defined in
`HUBS_3D[]` with anatomical direction vectors:

| id      | label             | region      | dir (x,y,z)              | on cerebellum? |
|---------|-------------------|-------------|--------------------------|----------------|
| ideas   | Ideas & projects  | Frontal     | -0.45, +0.80, +0.40      | no |
| journal | Daily journal    | Prefrontal  | -0.75, +0.55, +0.35      | no |
| health  | Health metrics   | Cerebellum  | +0.30, -0.85, -0.30      | **yes** |
| people  | People            | Temporal    | -0.55, -0.30, -0.55      | no |
| travel  | Travel            | Parietal    | +0.55, +0.20, +0.75      | no |

`computeHubPositions()` normalizes each direction, then snaps it to the actual
surface (cortex or cerebellum) at `1.05–1.06×` the radius so the hub orb sits
**just outside** the cloud rather than embedded in it. Re-run this after any
shape-parameter tweak.

Hub rendering:
- Each hub is a `THREE.Sprite` with a 128×128 canvas radial-gradient texture
  (white core → pale-blue ring → transparent).
- Base scale `0.30 ± 0.025·sin(t·1.4 + i)` — staggered breathing pulse per hub.
- When a hub is `activeHub` (hovered or expanded), multiply scale by `1.55`.
- Three.js raycaster picks against `hubMeshes` for hover and click.

### HTML labels (overlay)

Each frame, every hub's world position is projected to screen via
`Vector3.project(camera)` and the 0..1 NDC is converted to pixel coords inside
the canvas's bounding rect. `setHubScreen()` is called every other frame
(throttle) and React renders absolutely-positioned `<div>` labels at those
coords. Label content per hub: small mono region eyebrow, italic
Cormorant-Garamond label, low-contrast stat. Labels fade as `v.z` (post-projection
depth) crosses 0.55 — back-of-head labels become transparent.

### Interaction

- **Drag to rotate.** `pointerdown` on the canvas sets `dragging = true` and
  disables auto-rotation. `pointermove` accumulates `dx · 0.005` into `rotY`
  and `dy · 0.005` into `rotX` (clamped to ±1.3 rad to prevent flipping). The
  root group's actual rotation lerps toward target at 0.12 per frame.
- **Auto-rotate.** Until the user first drags, `rotY` ticks `+0.0018` per
  frame.
- **Hover and click on hubs** are routed through Three.js raycasting against
  the hub sprites. `onHubHover(idx | null)` and `onHubClick(idx)` are passed in
  as props.

### Resize

A `ResizeObserver` on the mount node updates camera aspect and renderer size
on every container resize. Don't lock the canvas to `window.innerWidth` —
use the container.

## Floating thoughts (`floating-thoughts.jsx`)

Ambient "top of mind" prompts surfacing in the dark space around the brain.
Six fixed normalized slots:

```
(0.12, 0.18) left-aligned    (0.88, 0.20) right-aligned
(0.18, 0.50) left-aligned    (0.82, 0.50) right-aligned
(0.10, 0.78) left-aligned    (0.88, 0.80) right-aligned
```

Each slot independently runs an 8–13s lifecycle:
- Fade in over the first 18% of life (smoothstep)
- Hold full opacity 18–78%
- Fade out over the last 22%
- Drift up at 0.004 px/ms during life

Two lines per thought:
- Kind tag — uppercase mono 8.5px tracked 2 in accent at 60% opacity:
  `ASKING`, `NOTICING`, `PATTERN`
- Thought text — Cormorant Garamond 17px, weight 300, italic if a question,
  color `#e6f4ff`

When a thought ends, the slot picks a new one not currently shown elsewhere.
There's a 200ms gap before the next mounts. Pool of 15 thoughts in `THOUGHTS[]`
(`floating-thoughts.jsx`) — final copy.

Hidden when a panel is open (`expanded !== null`).

## State & data flow

A single `BrainPage` component owns:
```
hover:    number | null          // idx of hovered hub
expanded: number | null          // idx of expanded hub
anchor:   { x: number, y: number }  // 0..1 viewport coords for panel grow
route:    'brain' | 'health'
askValue: string
```

`Brain3D` is presentational — `(onHubHover, onHubClick, activeHub,
expandedHub) → react node`. It owns its own Three.js scene, animation loop,
resize observer, and HTML-label state. `FloatingThoughts` owns its own slot
state (no parent coupling). `NeuronPanel` reads `BRAIN_CATEGORIES[catIdx]`
and `NEURON_CONTENT[cat.id]`.

Hub-click flow:
1. User clicks a hub (raycaster hit inside Three.js scene).
2. `onHubClick(idx)` fires.
3. `BrainPage` queries `[data-hub-idx="N"]` in the DOM to read the **HTML
   label's** bounding rect (the label is at the projected screen position),
   converts it to 0..1 anchor.
4. `setExpanded(idx)`; panel mounts and animates in from the anchor.

No data fetching is wired in this prototype — all content is hard-coded. In
production:
- `BRAIN_CATEGORIES` (counts, recency) → fetch from each data source's index.
- `NEURON_CONTENT` → AI-synthesized at first paint or background-cached.
- `THOUGHTS` → personalized, regenerated periodically.

## Recommended implementation path

1. **Scaffold a React component** that wraps the Three.js scene. If your
   codebase uses `@react-three/fiber`, port the imperative `useEffect` block
   into declarative R3F primitives; the math (cluster generation, color
   formula, raycasting) stays the same. If not, the imperative pattern in
   `brain-3d.jsx` translates almost 1:1.
2. **Reproduce the shape functions verbatim** — `cortexRadius`,
   `cerebellumRadius`, `fissureKeep`, `computeHubPositions`. These are the
   identity of the design.
3. **Generate the particle BufferGeometry** at mount time using the seeded RNG
   so the brain looks the same on every reload.
4. **Match the canvas sprite textures** for points and hubs — they're the
   reason the cloud glows. Don't drop them for solid points.
5. **Layer the HTML chrome** (wordmark, date, caption, hover chip, ask-bar,
   panel, floating thoughts) on top of the canvas in the same component tree.
6. **Wire the hub click → panel anchor → grow animation** path. Read the
   anchor from the projected HTML label position, not the orb's world
   coordinates.
7. **Re-tint the neuron panel** from warm-gold to icy-blue (see Neuron panel
   section).
8. **Move all `<style>{@keyframes …}</style>` blocks** into a single global
   stylesheet or your styled-components / CSS module setup.
9. **Consolidate `ICE` palette + `BRAIN_CATEGORIES`** — they're duplicated
   across files in the prototype; in production, one shared theme/data module.

## Performance notes

- Total particle count is approximately:
  `N_CORTEX_CLUSTERS · PARTICLES_PER_CLUSTER_AVG · ~1.0 +
   N_CEREB_CLUSTERS · 0.6·PARTICLES_PER_CLUSTER_AVG +
   N_CORTEX_FOG ≈ 19,000–22,000 points.`
  Single `THREE.Points` draw call — cheap on any modern GPU.
- `setPixelRatio(min(devicePixelRatio, 2))` caps retina cost.
- The HTML label `setState` is throttled to every other frame.
- Per-frame React state for chrome breathing (in the 2D version) is heavier
  than necessary — for the 3D version, all per-frame motion lives inside the
  Three.js render loop, which is the right architecture.
- Additive blending + `depthWrite: false` is required for the soft glow but
  means particle order doesn't matter — don't sort.
